# Клиентское приложение поиска автозапчастей и аналогов

Интеграция с внешним веб-сервисом **«Проценка»** компании ООО «ЮРАЛ» (Favorit-parts). Приложение обеспечивает двухэтапный процесс подбора номенклатуры, корректную обработку состояний загрузки и отказоустойчивость при сбоях сети.

## Стек технологий
* **Библиотека:** React (Hooks, Функциональные компоненты)
* **Стейт-менеджмент:** Redux Toolkit + RTK Query (Server State Management)
* **Стилизация:** Bootstrap 5 (Адаптивная сетка, компоненты)
* **Сборщик:** Vite

---

## Архитектурные решения и фичи

### 1. Двухэтапная императивная логика (Lazy Queries)
Процесс поиска строго разделен на два независимых этапа согласно ТЗ:
* **ЭТАП 1 (Поиск брендов):** Реализован через декларативный хук `useGetBrandsQuery`. Запрос отправляется автоматически при фиксации артикула из формы поиска.
* **ЭТАП 2 (Аналоги и склады):** Реализован через ленивый хук `useLazyGetAnalogsQuery`. Использование ленивого триггера `triggerGetAnalogs` позволило полностью изолировать второй этап от первого. Запрос улетает императивно, строго по событию клика на конкретный бренд, что защищает бэкенд от избыточных холостых запросов при изменении текста в инпуте.

### 2. Оптимизация UI-лоадеров и кэширования
* Состояния загрузки внутри компонентов `BrandList` и `PartsTable` отслеживаются через флаг **`isFetching`** вместо `isLoading`. Это гарантирует, что спиннер загрузки честно отображается при каждом повторном запросе или переключении между брендами, исключая визуальное «залипание» старых данных на экране.
* Использование встроенного кэширования RTK Query обеспечивает мгновенный рендеринг данных из оперативной памяти при повторном обращении к уже загруженным связкам (артикул + бренд).

### 3. Чистота кода и паттерн Early Return
Вся ветвящаяся логика отображения внутренних состояний интерфейса (*Загрузка*, *Глобальная ошибка*, *Приветственный экран*, *Пустой ответ*, *Вывод данных*) вынесена из JSX-разметки в линейные функции `renderContent` с использованием паттерна **Early Return (Ранний возврат)**. Это исключило нагромождение логических операторов `&&` в верстке, сделало компоненты легко тестируемыми и обеспечило стабильность сетки Bootstrap (Layout Shift) при любых сценариях.

### 4. Бизнес-логика обработки данных API
* **Развертывание складов:** В соответствии с требованиями документации API (стр. 1-2), данные о ценах и доступных остатках извлекаются непосредственно из массива конкретных складов **`warehouses`** каждого товара. Логика реализована через метод `flatMap`, формируя независимые строки предложений для удобства закупщика.
* **Признак невозвратности:** В таблице предложений визуально обрабатывается и подсвечивается маркер `notRefund` (невозвратная позиция поставщика).

## 🛠️ Настройка и запуск проекта

### 1. Переменные окружения (`.env`)
Для работы приложения с публичным тестовым ключом «Проценки» в корне проекта настроена безопасная цепочка подстановки. Проект работает «из коробки», но при необходимости ключ можно переопределить.

Создайте файл `.env` в корне проекта по образцу:
```env
VITE_API_KEY=00000000-0000-0000-0000-000000000001
```

### 2. Запуск в локальном окружении
```bash
# Установка зависимостей
npm install

# Запуск сервера разработки (Vite)
npm run dev
```

*Примечание: Локальное проксирование для обхода политик CORS настроено внутри `vite.config.js` через прокси-сервер для путей `/hs`.*
